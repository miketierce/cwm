# Lab Diary — June 30, 2026

## Scrappy nonlinearity hunt + RX board overheat/short (paused)

Goal: get a nonlinear cascade WITHOUT ordering parts — make the analog link clip/rail so it
produces real intermod (the linear cascade gives IMD3 −27 dBc = nil).

### What we tried (all on U1, the rank-1 cascade channel)
1. **Why gain-cranking can't work (GBW wall):** OPA2134 GBW 8 MHz; at 40–130 kHz the max usable
   gain before roll-off is ~80×. Smaller Rg ≠ more swing → can't rail by gain. Confirmed reasoning.
2. **Reverse-feedback Schmitt** (move Rf2 from −IN B/j8 to +IN B/j9 = positive feedback → comparator).
   Probed U1 OUT B (pin 7) on Ch B: **latched at +rail, no swing.**
3. **R_b2 swap 100k→1k** (drop +IN DC bias): still latched.
4. Probed stage-1 OUT A (pin 1), AC-coupled: only ~90 mV noise (H1≈H3≈H5) = **no clean signal**.
5. **Root cause of the "railed" reads: the drive/preamp board was UNPLUGGED** during those probes —
   U1 had no supply, so its outputs floated to a rail. NOT a dead chip. (The earlier
   cascade_verify "67× all OK" was also suspect — likely plate-A direct leak, not true cascade.)

### Parts reality
- **BPW34 photodiode = a real Si diode** → could be a half-wave clipper, BUT the pack is misplaced.
- **OPT101P (×2) = photodiode + transimpedance amp = a LIGHT sensor, NOT an electrical clipper.**
  No accessible diode junction; coercing its internal op-amp is fragile + light-contaminated. Its real
  use is the **optical readout (WL-B1)**: laser → foil/mirror on a plate → OPT101 → V; nonlinearity
  appears at the **beam edge** (beam walk-off = hard optical clip, no GBW limit). Deliberate build, not a hack.

### Re-plug + NCO power-cycle
- Drive came back strong (700–1200× all channels) — **PIO block (CH1–8) had halted; power-cycle fixed it.**
- BUT **RX (Ch A readout) went to noise on ALL 15 channels** (1.8–3.3×) = common readout-path fault,
  not the plates. Same class as the June-28 dead-half readout bug (drive present, RX flat).

### FAILURE EVENT — RX board shorted/overheated
While chasing the dead readout, **something on the RX board overheated** — burning smell, board warm
to the touch on the bottom; user disconnected power. **Board is now disconnected; do NOT re-power until
the shorted/overheated component is found.** Prime suspects (cold inspection): reversed −9 V electrolytic
(the "flipped" one in the build — reverse-bias → vents/heats), solder bridge across ±9 V/AGND, or an
op-amp output shorted to a rail. Look for discoloration / bulge / one part hotter than neighbors / bridges.

### Status / what STANDS (independent of this hardware fault)
- The **publishable results are already captured in data** and are unaffected:
  767-mode linear kernel (census 220731), Pong 256-state 97%, 2 h drift-free soak,
  and the corrected content-addressable-memory findings: partial-query completion (glass 84% vs wire 47% @σ1)
  + 90%-mode-dropout tolerance (83%). The fair baseline retracted the "denoising vs wire" claim.
- Nonlinearity: **not achieved.** Linear cascade stands. Electrical-clipper path exhausted (no parts);
  optical (OPT101+laser) is the real future route.

### Lessons
- Never probe with DC-coupled Ch B on an unknown ground ref — it pegged and sent us chasing a phantom dead chip.
- Verify SUPPLY/POWER state before diagnosing op-amp "rail" behavior.
- The RX readout path is the fragile, repeatedly-failing subsystem (dead-half June 28; short June 30).
- Stop-and-protect: the array's value is the stored kernel + analysis, not the bench staying up.

### Next when resumed
1. Cold-inspect RX board; find + fix the overheated component BEFORE any power.
2. Re-verify with cascade_verify once readout is restored (target: RX 24–32×).
3. Park nonlinearity; if pursued, build the OPT101 optical readout deliberately (WL-B1), not a scrappy clip.
