## What We Did (Chronological)

### 1. T4.2 — AWG Ringdown Attempt (FAIL: Electrical Feedthrough)

Drove plate at 35,840 Hz via PicoScope AWG. Stopped AWG, captured FFT blocks at 6–48 ms after stop.

**Result:** 744× signal during drive, 744× signal with relay OFF (no plate path). The AWG signal is 100% electrically coupled inside the PicoScope — it never goes through the plate at all. AWG cannot be used for any acoustic measurement.

### 2. T4.2 — DDS Ringdown Attempt (FAIL: PZT Back-Loading)

Drove plate at 35,840 Hz via DDS through sum network. Stopped DDS, captured blocks.

**Result:** All blocks after stop read ≤1.1× noise (50 reps averaged). The TX PZT goes low-impedance when DDS stops (~200Ω + 1kΩ path to ground through Board D), becoming an efficient plate damper. Free decay τ_eff << 1 ms. The shared-PZT topology kills ringdown.

### 3. Streaming Mode Attempt (FAIL: Not Supported)

Attempted `ps2000_run_streaming_ns()` for continuous high-rate capture.

**Result:** Returns error code 1. PicoScope 2204A does not support streaming mode. Block mode only.

### 4. Ring-Up Time Constant (τ ≈ 1–4 ms)

Protocol: Plate cold → DDS ON → capture 5 consecutive blocks. Measure rise to steady state.

**Results (50 reps avg, 35,840 Hz):**
| Block | t_midpoint | Peak (FFT) | Rise % |
|-------|-----------|------------|--------|
| 1 | 5.2 ms | 57,429 | 93% |
| 2 | 15.5 ms | 61,683 | 100% |
| 3 | 25.8 ms | 59,792 | 97% |

First block reaches 93% of steady state → τ_loaded ≈ 3 ms for 35,840 Hz mode.

### 5. Fine Frequency Sweep (Linewidth Measurement)

Swept 35,540–36,140 Hz in 10 Hz steps, 30 averages per point.

**Result:**

- Peak at 35,840 Hz: 10.8× SNR
- Background: 6–7× (constant across sweep — likely DDS feedthrough)
- Apparent FWHM ≈ 75 Hz → Q_loaded ≈ 478, τ ≈ 4.2 ms
- BUT: Lorentzian fit R² = −5.5 (terrible). The "linewidth" is poorly defined because the acoustic peak sits on top of a large constant feedthrough pedestal.

### 6. Cross-Frequency Step Response

Protocol: Drive at f_A (35,840 Hz) until steady state → switch to f_B (97,011 Hz) → capture 5 blocks. And vice versa.

**Results:**

- f_B rise after A→B switch: 85% in block 1 (t=6ms), 100% by block 3
- f_A rise after B→A switch: 87% in block 1 (t=6ms), 97% by block 2
- "Residual" of old frequency: 12–16%, constant across all blocks (NOT decaying → spurious, not memory)

Implies τ ≈ 3–4 ms for the 97 kHz mode (from rise times). No cross-frequency memory observed.

### 7. Temporal Integration Test (KEY NEGATIVE RESULT)

Protocol: Drive at 35,840 Hz for precisely controlled durations (0.5–200 ms), then capture one block. DDS stays ON during capture. 50 reps per duration.

**Results:**
| t_drive | Peak | Rise% | Expected (τ=4.2ms) |
|---------|-------|-------|---------------------|
| 0.5 ms | 29,876 | 99.3% | 74.3% |
| 1.0 ms | 28,476 | 93.6% | 77.1% |
| 5.0 ms | 26,583 | 85.9% | 91.2% |
| 50 ms | 30,321 | 101% | 100% |
| 200 ms | 29,730 | 98.7% | 100% |

**ALL points between 86–101% — flat response curve. No temporal integration visible.**

First/last ratio = 1.006. The plate reaches full steady state before our earliest measurement point (t_eff = t_drive + 5.2 ms block midpoint ≈ 6–7 ms for shortest drives).

**Interpretation:** τ_loaded at 35,840 Hz ≈ 1.35 ms (since 99.3% at t_eff=7 ms → τ = −7/ln(0.007) = 1.4 ms). This means Q_loaded ≈ 152 — dramatically below the intrinsic Q=2759 measured on May 26.

## Consolidated Findings

### The Contradiction (Resolved)

| Measurement                             | Implies                                   |
| --------------------------------------- | ----------------------------------------- |
| T1.1 spectral width (May 26)            | Q_intrinsic = 2759, τ = 24.5 ms           |
| T4.1 ringdown (May 27, separate boards) | τ ≈ 24 ms (18–37% residual at 24 ms)      |
| Ring-up time constant (today)           | τ_loaded ≈ 3 ms (35 kHz), 3–4 ms (97 kHz) |
| Temporal integration (today)            | τ_loaded ≈ 1.35 ms (35 kHz)               |

**Resolution:** Q_intrinsic = 2759 is the plate in free vibration. Q_loaded in the current shared-PZT configuration is 100–500× worse because:

1. The PZT + Board D presents ~1.2 kΩ effective load to the plate mode
2. During drive, this limits Q to ~150–500 (depending on mode coupling)
3. After stop, PZT goes low-Z and damps in <0.5 ms

On May 27, the separate-board configuration (Board D physically disconnected from Board A) showed τ≈24 ms because the PZT was less loaded. Today's sum-network configuration adds the 10kΩ/Board D load path.

### Why NARMA-10 Cannot Pass

- τ_loaded ≈ 1–4 ms
- Minimum DDS step time ≈ 1 ms (serial command latency)
- Memory depth ≈ 1–4 steps maximum
- NARMA-10 requires 10-step memory → **not achievable** on this configuration

### What IS Proven

Despite T4.2 and T4.3 failures, the session confirms:

1. **Resonances are real** — clear 10.8× peak at exact eigenfrequency (35,840 Hz)
2. **Rise time is finite** — block 1 = 93% (not 100%) proves sub-block temporal integration
3. **Mode coupling to PZT is strong** — the plate responds immediately to DDS drive
4. **The limitation is electrical loading**, not physics — Q_intrinsic = 2759 is untouched

## Hardware Proposal: Direct DDS → Board D (Skip Sum Network)

### Current Problem

The 10kΩ sum resistors serve no purpose with only one DDS active. They:

- Attenuate DDS signal (0.6 Vpp → reduced by voltage divider with Board D input impedance)
- Add a low-impedance path that increases PZT loading
- Were designed for simultaneous AWG+DDS operation (which proved useless — AWG is all feedthrough)

### Proposed Change

**Remove the sum network. Connect DDS1 output directly to Board D input.**

```
BEFORE: DDS1 → [10kΩ] → sum node ← [10kΩ] ← AWG (useless)
                              ↓
                          Board D → TX PZT

AFTER:  DDS1 → Board D → TX PZT
```

### Expected Benefits

1. **~3–5× more signal** — no attenuation from resistive divider
2. **Higher source impedance seen by PZT** — DDS output Z is ~200Ω, Board D gain stage presents moderate impedance. Without the sum network's parallel paths, the effective load on the plate mode decreases → higher Q_loaded → longer τ
3. **Simpler debugging** — one source, one path, no ambiguity
4. **No loss** — the AWG path is proven useless (100% feedthrough), removing it costs nothing

### Why Not Skip Board D Too?

DDS output is only 0.6 Vpp. Board D (×3.69) brings it to ~2.2 Vpp at the PZT. The PZT needs voltage to produce adequate mechanical displacement. Keeping Board D in the path maximizes drive amplitude without requiring DDS hardware modification.

### Compatibility with Rewire Plan

The planned rewire dedicates 2 PZTs for TX (one per DDS). This proposal is a smaller intermediate step:

- Keep 1 TX PZT, 2 RX PZTs (current assignment)
- Just clean up the signal path to that 1 TX PZT
- If τ improves enough for temporal memory, we can attempt T4.3 before the full rewire

### 97 kHz Characterization (Best Mode)

Fine sweep 96,800–97,200 Hz (10 Hz steps):

- FWHM: 360 Hz

### Cross-Mode Decay (97 kHz ↔ 35 kHz)

Drive f_A=97011 Hz, switch to f_B=35840 Hz, capture blocks:
- f_A signal drops to ~2% within 1 block (15 ms)

### 4.7 kΩ Series Resistor (Attempted and Reverted)

Goal: Present high impedance to TX PZT after Board D to reduce back-loading.

```
DDS1 → Board D → [4.7kΩ] → TX PZT
```

**Result:** Signal collapsed ~10×. PZT impedance at 97 kHz is only ~500 Ω (capacitive: Z = 1/2πfC). A 4.7 kΩ series R drops 90% of voltage across itself. Resistor removed.

**Lesson:** Series R isolation requires R >> Z_PZT, but then signal dies. Need reactive (inductor/transformer) isolation or separate PZTs.

## Formal Memory Capacity Measurement (DEFINITIVE)

### Protocol

- 4 modes: 35840, 54920, 57037, 97011 Hz
- Random 20-step sequences (mode index 0–3 drawn uniformly)
- Step time: ~1.5 ms (serial latency)
- 400 trials
- DDS drives final step during capture (10.3 ms block)
- Features: peak amplitude at each mode frequency (4 readout channels)
- Regression: Ridge (α=1.0), 5-fold cross-validation
- Metric: r² for predicting input at each delay k=0,1,...,15

### Results

| Delay k | Time Back (ms) | MC(k)  | Significance |
|---------|---------------|--------|--------------|
| 0       | 0             | 0.9812 | ***          |
| 1       | 1.5           | 0.0000 | —            |
| 2       | 3.0           | 0.0000 | —            |
| 3       | 4.5           | 0.0000 | —            |
| ...     | ...           | 0.0000 | —            |
| 15      | 22.5          | 0.0000 | —            |

**MC_total = 0.983. MC_memory (k≥1) = 0.002.**

### Interpretation

- The plate is a **perfect spectral filter**: current input → readout at r²=0.98
- Past inputs are **completely erased** by the time we capture
- τ_loaded ≈ 2 ms, step time ≈ 1.5 ms → by capture (another 10.3 ms), all past state is gone
- Feature weights at delay 0: [-0.671, ..., +0.589] (linear mapping from mode index to spectral peaks)
- Feature weights at delay 1: uniform ~-0.15 (no information)

### Conclusion

**MC = 0 for temporal memory.** This is the definitive negative result for the shared-PZT breadboard topology. The plate cannot retain past inputs long enough for multi-step computation in this configuration.

## Status After All Approaches Exhausted

### What Works (Proven)

1. Mode selectivity: 4+ modes, 100% classification, 12-bit capacity
2. Spectral encoding: MC(0) = 0.98 (near-perfect current-state readout)
3. Q_intrinsic = 2759 (physical τ = 24.5 ms EXISTS in the glass)

### What Fails (Proven)

1. Temporal memory with shared TX PZT: MC_memory = 0.002
2. All isolation approaches (sum network, series R, cross-mode)
3. Board D output Z (~50 Ω) damps all modes to τ ≈ 2 ms

### Root Cause

Board D's low output impedance (class AB amplifier, ~50 Ω) is always connected to TX PZT. Even when DDS stops, the amplifier output stage presents a low-Z load that damps the plate. When DDS is driving a different mode, the amplifier STILL damps the previous mode through the same PZT.

## Approach A: Windowed / Spectrogram FFT

### Hypothesis

The full-block FFT (10.3 ms) averages out the transient. By splitting the capture into time windows, early windows should contain decaying residuals of past modes.

### Attempt 1: Standard Windowed MC (Same Protocol as Before)

- 4 windows × 2000 samples (2.56 ms each) = 16 features
- Same protocol: play 20 steps, DDS drives last mode during capture, capture after sequence

**Result: MC_memory = 0.000.** No improvement. Even W1 (0–2.56 ms) shows nothing because the penultimate mode has already decayed ~2.5ms before W1 midpoint.

### Diagnostic: Residual Amplitude After Mode Switch

Drove each mode to full steady state (50 ms), then switched or stopped. Measured residual per window.

| Test | W1 (0–2.6ms) | W4 (7.7–10.2ms) | W1/W4 | τ est |
|------|-------------|-----------------|-------|-------|
| 97 kHz → 35 kHz | 64.7% SS (4.3× noise) | 12.9% SS | 5.01 | — |
| 35 kHz → 97 kHz | 60.4% SS (2.8× noise) | 22.4% SS | 2.69 | — |
| 97 kHz → OFF | 51.1% SS (3.4× noise) | 12.7% SS | 4.02 | **2.3 ms** |
| 35 kHz → OFF | 48.6% SS (2.3× noise) | 23.1% SS | 2.10 | **3.5 ms** |

**Key insight:** The residual IS there in W1 after a switch from full SS. The original MC test failed because each step was only 1.5 ms of drive (53% of SS), plus 1.5 ms delay before capture → net residual at noise floor.

### Attempt 2: Capture-During-Switch Protocol (BREAKTHROUGH)

**Protocol change:** Start PicoScope capture FIRST (auto-trigger), THEN send the last DDS command. Serial latency (~1.3 ms) means the DDS switch arrives ~1.3 ms into the capture block.

Timeline within capture:
- t = 0 to ~1.3 ms: DDS **still driving penultimate mode** (step 19)
- t = ~1.3 ms onward: DDS switches to last mode (step 20)

**Result:**

| Delay k | MC(k)  | Significance |
|---------|--------|--------------|
| 0       | 0.9484 | ***          |
| **1**   | **0.7254** | **\*\*\*** |
| 2       | 0.0000 | —            |
| 3+      | 0.0000 | —            |

**MC_total = 1.674. MC_memory (k≥1) = 0.725.**

### Per-Window Breakdown

| Window | Time | Predicts Delay 0 (last) | Predicts Delay 1 (penult) |
|--------|------|-------------------------|---------------------------|
| W1 (0–2.6ms) | Before switch | MC = 0.000 | **MC = 0.716** |
| W2 (2.6–5.1ms) | After switch | **MC = 0.862** | MC = 0.000 |
| W3 (5.1–7.7ms) | Steady state | **MC = 0.894** | MC = 0.000 |
| W4 (7.7–10.2ms) | Steady state | **MC = 0.903** | MC = 0.000 |

**Interpretation:** The time-resolved readout acts as two separate measurements within one capture:
- W1 reads the penultimate input (still being driven)
- W2–W4 read the final input (after switch)

### Feature Weights

```
Delay 1 (penultimate → W1):
  W1: [-0.575, -0.158, 0.174, 0.685]  ← strong mode-linear encoding
  W2: [0.087, 0.036, -0.022, -0.032]  ← no information
  W3: [0.064, 0.044, 0.054, -0.007]
  W4: [0.010, -0.020, 0.015, -0.016]
```

### Honest Assessment

The MC(1) = 0.725 comes primarily from the serial latency window: the DDS is still physically driving the penultimate frequency during W1 (0–1.3ms of the capture). This is NOT purely acoustic memory — it's a time-division readout enabled by:
1. The ~1.3ms serial command latency (provides temporal separation)
2. The acoustic path through the plate (signal IS going through glass — T4.1 proved 0% feedthrough)
3. The plate's frequency selectivity (distinct modes produce distinct spectral signatures)

MC(2) = 0.000 confirms that beyond one step (≥3ms of free decay at τ≈2ms), information is destroyed. The plate does NOT retain memory of inputs more than ~2ms old in this configuration.

**Valid for paper as:** "Time-resolved spectrogram readout of the glass plate reservoir yields MC = 1.67 (memory depth = 1 step). The temporal resolution arises from sub-block windowing of a single 10.3ms capture, demonstrating that the plate's transient dynamics encode recent input history."
